# 设计宝运营预警工作台生产 V1 设计说明

## 1. 建设目标

将已确认的静态原型升级为可每日使用的生产系统。管理员上传 Excel 后，系统完成数据校验、项目与商家匹配、指标计算、历史快照、商家分类与预警生成；大区和城市负责人可通过首页、指标中心、商家中心和项目中心发现问题并下钻到事实明细。

V1 的核心闭环为：

`每日 Excel → 数据校验 → 指标快照 → 规则判断 → 首页预警 → 商家/项目下钻`

## 2. 用户与数据权限

V1 提供三类角色：

- 管理员：上传数据、查看全国数据、查看导入错误、执行商家豁免/排除、确认 C 类建议。
- 大区负责人：查看被授权大区及其城市、商家和项目数据。
- 城市负责人：仅查看被授权城市、该城市商家及项目数据。

所有列表、统计、指标和导出查询都必须在服务端应用组织范围，前端筛选不能扩大用户权限。

## 3. V1 功能范围

### 3.1 前台

- 首页：今日总览、辅导执行异常、商家改善异常、项目异常、A/B/C 结构及变化。
- 指标中心：40 个文档指标和 SOP 执行达标率；单指标分析与多指标组合分析；支持全部勾选；大区→城市→商家→项目下钻。
- 商家中心：A/B/C/已淘汰、分类变化、SOP 达标率、辅导、改善、异常项目、签约、最后分派时间。
- 商家详情：分类原因、状态时间线、14 天观察期、指标趋势和项目明细。
- 项目中心：异常优先、组织/时间/状态/商家分类筛选，以及项目完整详情。

### 3.2 管理能力

- 每日 Excel 上传、重复文件识别、字段校验、错误明细和导入历史。
- 原始文件保存、原始行留痕、项目当前状态更新、每日不可变快照。
- 指标日/周/月快照计算；周口径固定为周日 00:00 至周六 23:59:59，时区为 Asia/Shanghai。
- 规则命中记录、商家分类快照、C 类人工确认、临时豁免和永久排除。
- 所有人工操作保存操作人、时间、原因和前后值。

## 4. 暂不进入 V1

- 通用可视化规则编辑器；V1 使用版本化固定规则。
- 任务指派、截止时间、跟进记录和消息通知。
- 多标签画像、移动端专项版本、与第三方 CRM 自动同步。
- 自动修改原始 Excel 数据。

## 5. 数据架构

### 5.1 核心事实

- `organizations`：全国、大区、城市层级。
- `merchants`：商家事实属性，不保存人工维护的当前 A/B/C 作为源数据。
- `projects`：项目稳定事实和当前最新状态。
- `project_snapshots`：每个数据日的项目字段快照，导入后不可覆盖。
- `upload_batches`、`upload_rows`、`upload_errors`：上传、原始行和错误追溯。
- `metric_definitions`：指标名称、指标组、单位、方向、计算模式和下钻能力。
- `metric_snapshots`：日/周/月、组织/商家层级的指标值、分子、分母和来源批次。
- `merchant_classification_snapshots`：每周正式分类、原因和生效时间。
- `rule_hits`：项目/商家命中规则的事实记录。
- `merchant_overrides`：C 类确认、临时豁免、永久排除和人工调整记录。
- `users`、`user_scopes`、`sessions`、`audit_logs`：身份、组织权限与审计。

### 5.2 导入策略

Excel 采用“全量 + 状态变化”处理：

1. 计算文件 SHA-256，阻止同一数据日的完全重复文件。
2. 将各 Sheet 映射到统一字段；稳定主键为商家 ID 和项目 ID。
3. 先写入暂存区并执行必填、枚举、日期、唯一性和组织归属校验。
4. 存在不可恢复错误时整批不入正式表；警告允许入库但需在结果页展示。
5. 项目 ID 已存在则更新最新状态，不存在则新增；同时生成当日不可变快照。
6. 导入成功后触发指标、规则、分类和首页聚合计算。

指标既支持从项目事实计算，也支持导入 Excel 汇总值。能够由明细计算的指标以计算值为准，并与汇总 Sheet 进行差异校验；只能由汇总 Sheet 提供的指标保存为 `IMPORTED` 来源。

## 6. 指标口径

指标目录包含 6 组 40 个文档指标（以实际“总数据（设计宝）”指标行校正）：

- 分派-开口：8 个。
- 开口-PK：2 个。
- 结果转化：12 个。
- 设计师 SOP 执行：6 个。
- 群信息同步：6 个。
- 群聊质量：6 个。

另增加管理指标“商家 SOP 执行达标率”。单个项目只有同时满足以下条件才达标：

- 30min 内跟进 = 是。
- 详细需求沟通/户型解析 = 是。
- 硬约沟通/量房 = 否。

硬约沟通/量房为反向指标；`是、是、是`仍判定为未达标。

指标中心规则：

- 1—8 个指标使用趋势折线对比。
- 9 个及以上自动使用分组指标矩阵。
- 不限制勾选数量，可一次勾选全部 40 个文档指标。
- 日、周、月和自定义时间均由同一查询接口返回，比例指标同时返回分子和分母。

## 7. 预警与商家分类

### 7.1 项目异常

项目异常不设等级，满足任一条件即进入异常项目列表：

- 当天数据标记需辅导。
- 改善情况 = 否。
- 是否辅导为空白。

项目列表只负责提示达标/未达标和运营状态，SOP 细分原因在项目详情与指标中心展示。

### 7.2 商家分类

- A 类：SOP 执行达标率 ≥60%，且当月有签约项目。
- A 类风险关注：达标率 <60% 或当月未签约；只预警，不立即降级。
- B 类候选：SOP 达标率在 40%—60%，连续 2 周下降，且过程指标低于城市平均；观察期 14 天。
- B 类改善：按每周更新机制重新判断，满足 A 类条件后回 A。
- C 类候选：B 类 14 天观察期结束未改善，或 SOP 达标率持续低于 40%；必须人工确认后进入 14 天挽回观察期。
- 已淘汰：最后一次项目分派距当前数据日 ≥14 天且无新增分派项目。

规则优先级为：生命周期淘汰 > C 类 > B 类 > A 类风险关注。所有命中必须保存使用的指标值、规则版本和可读原因。

## 8. 系统边界与模块

- Web 应用：页面、服务端查询接口、上传入口和组织权限。
- 导入工作进程：解析 Excel、校验、入库、生成快照。
- 指标模块：指标目录、公式、周期聚合和下钻查询。
- 规则模块：项目异常、商家分类、规则命中和人工覆盖。
- PostgreSQL：业务事实、快照、权限、作业和审计。
- 对象存储：原始 Excel 文件和导入结果附件。

上传接口只创建作业，不在浏览器请求中完成全部计算。工作进程通过 PostgreSQL 作业表领取任务，避免 V1 引入额外消息队列。

## 9. 异常处理

- 上传失败不能覆盖上一成功数据日，前台继续显示最后一次成功更新时间。
- 指标分母为 0 时返回 `null`，页面显示“—”，不能显示 0% 或计算错误。
- 未识别商家、重复项目 ID、非法枚举和错误日期作为阻断错误。
- 可选字段为空作为警告并保留为空；“空白”和“否”必须严格区分。
- 重跑同一成功批次必须幂等，不得生成重复快照或重复规则命中。
- 计算失败记录失败阶段和错误摘要，允许管理员从失败阶段安全重试。

## 10. 验收标准

1. 管理员可上传一份样例 Excel，并查看成功数、警告数、错误数和错误行。
2. 同一文件重复上传被识别；失败批次不影响现有前台数据。
3. 40 个文档指标全部可搜索、分组、单选、多选和全部勾选。
4. 周日—周六周口径、周环比、月趋势和自定义时间结果一致可复算。
5. 指标可从全国/大区下钻至城市、商家和项目；组织权限无法越权。
6. SOP 达标严格按“是、是、否”计算，比例分子与明细项目可相互核对。
7. 项目三类异常、A/B/C/已淘汰规则、14 天观察期及人工确认均有历史记录。
8. 首页预警可在三次点击内到达具体项目，关闭详情后保留筛选上下文。
9. 1440×900 与 1280×800 桌面尺寸无页面级横向溢出。
10. 核心单元、集成和浏览器测试通过；生产环境有健康检查、错误日志、每日备份和回滚说明。
