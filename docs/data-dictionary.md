# 设计宝生产 V1 数据字典

生产 V1 只读取上传工作簿中的 `项目明细2` 和 `工作表3`，其他子表不会参与导入。

## 子表关联

`项目明细2.A（城市）` 与 `工作表3.C（装企城市）` 精确匹配，以取得城市所属大区。城市在 `工作表3` 中缺失或对应多个大区时，整批导入失败并生成 `UNKNOWN_ORGANIZATION` 错误。

源文件允许同一个项目同时分派给多个装企，因此生产系统使用 `项目ID + 装企ID` 作为“项目分派记录”的稳定键；仅项目 ID 相同不算重复。同一组合在同一批次重复时生成 `DUPLICATE_PROJECT_ID`。

## 项目明细2

| 统一字段 | 当前表头/兼容别名 | 类型 | 必填 | 空白含义 |
|---|---|---|---|---|
| city | 城市、装企城市、你 | 文本 | 是 | 无法确定组织，阻断导入 |
| merchantId | 装企ID、商家ID、商户ID | 文本 ID | 是 | `MISSING_ID`，阻断导入 |
| merchantName | 装企名称、商家名称 | 文本 | 否 | 保留空白 |
| projectId | 项目ID、项目id | 文本 ID | 是 | `MISSING_ID`，阻断导入 |
| category | 类别 | 设计宝/小红书 | 否 | 保留空白 |
| assignedAt | 分派时间、分派时间1 | 日期 | 是 | `INVALID_DATE`，阻断导入 |
| followWithin30m | 30min内跟进、30分钟内跟进 | 是/否/业务备注 | 否 | 空白或业务备注保留 `null`，不等于否 |
| needsAnalyzed | 详细需求沟通或户型解析、详细需求沟通/户型解析 | 是/否/业务备注 | 否 | 空白或业务备注保留 `null`，不等于否 |
| hardInvite | 硬约沟通/量房 | 是/否/业务备注 | 否 | 空白或业务备注保留 `null`，不等于否 |
| needsCoaching | 是否需辅导装企、是否需辅导、需辅导项目 | 需辅导/无需辅导 | 否 | 保留 `null` |
| coached | 城市辅导结果（分公司填写）、是否辅导 | 已辅导/未辅导 | 否 | 保留 `null`，并用于“未辅导”预警 |
| improved | 辅导次日是否在群内有改变（总部检核填写）、是否改善、改善情况 | 是/否 | 否 | 保留 `null` |

SOP 达标仍按已确认口径计算：`30min内跟进=是`、`详细需求沟通或户型解析=是`、`硬约沟通/量房=否`。业务备注和空白均不按达标处理，但会保留原值供追溯。

## 工作表3

| 字段 | 表头 | 类型 | 必填 | 说明 |
|---|---|---|---|---|
| cityType | 城市类型 | 文本 | 否 | 同一城市可保留多个历史类型，V1 取首个值展示 |
| city | 装企城市 | 文本 | 是 | 与项目表城市匹配 |
| region | 大区 | 文本 | 是 | 同一城市只能对应一个大区 |

## 数据质量代码

阻断错误：`MISSING_ID`、`DUPLICATE_PROJECT_ID`、`INVALID_DATE`、`UNKNOWN_ORGANIZATION`、`INVALID_ENUM`。

非阻断警告：`OPTIONAL_VALUE_MISSING`、`SUMMARY_MISMATCH`。其中空白与“否”始终分开保存；“需辅导但辅导结果为空”和“已辅导但改善结果为空”会单独提示，不对所有正常空白重复报警。
